Why classifiers trained on cGAN crops score 97% on generated images and 60% on real ones

Date: 10/09/2026

GOHREP

Goal:

Explain a specific past result. Classifiers trained on cGAN-generated CDA crops reached about 97% on generated images but only ~60% on real ones (from_HPC/models_new/0004_CGAN_CNN/002_Model_B reached avg_vaf 0.9986 on GAN images; 0008_Transformers_GAN reached 0.9821 CV against 0.5462 real test accuracy). Three explanations are possible and they demand different fixes, so this analysis separates them before the new 512-config cGAN run is judged.

Hypotheses:

  1. Mode collapse / narrowness. The generator produces a narrow range within each class, so generated classes are trivially separable while real ones overlap. This is the intuitive explanation and the one worth testing first.
  2. Memorisation. The generator reproduces training crops, so a classifier is effectively trained on a subset of real data and the 97% is meaningless. The Frechet distance is actively blind to this – measured below, a perfectly memorising generator scores better on it than two halves of the real data do.
  3. A class-conditional shortcut. The generator marks each class with some consistent artefact – a colour cast, a texture – that a fresh classifier learns immediately but which does not exist in real crops. A conditional GAN is free to do this because its discriminator only asks whether an image looks real for its label, not whether the label is encoded the way it is in real data.

Rationale:

Hypotheses 1 and 3 are distinguished by where the class information lives. Under narrowness, generated classes separate well in the same terms real images do. Under a shortcut, they separate only in terms that a model trained on generated data invents for itself. A linear probe is the instrument for that distinction: logistic regression on a fixed feature space cannot invent new features, only reweight the ones it is given, so it answers “is the class already legible in this representation?” rather than “can some model find it somewhere”.

Two probes give a 2x2 that pins the answer down: fit on real and test on generated, and fit on generated and test on real. The 97%/60% experiment was the second of these with a CNN free to invent features; doing it with a linear model on fixed features says whether the information was in the shared representation all along.

Experimental plan:

  1. Diversity: within-class spread of generated crops against real ones, per class.
  2. Memorisation: nearest-real-neighbour distance for each generated crop.
  3. Linear probes both ways, on the CNN feature space.
  4. Locate the classes in feature space: are generated centroids where the real ones are?
  5. Repeat 1, 3 and 4 in a second, unfitted feature space and name the features the generator gets wrong.

Two feature spaces, because one of them has an obvious objection. Sections 2-5 work in the last pooling layer of the top medoid CNN, which is the same space src/cgan.py uses for the Frechet distance, so those numbers are directly comparable to the training metric. But that CNN was trained on real crops, so generated images are judged through a lens fitted to their competitor and some of the difference could be the lens.

Section 6 therefore repeats the measurements in the twelve hand-crafted Chapter 2 features – Otsu lesion segmentation plus means, spreads and pixel counts over the resulting regions. Nothing in them is fitted to either set. They are also interpretable, which the CNN space is not: each has a known meaning and a known direction, so a generated-vs-real disagreement can be named rather than merely measured. The port is checked against Chapter 2’s own published AUCs before anything is read off it.

2. Diversity: are generated crops narrower than real ones?

Within-class spread is the mean pairwise Euclidean distance between crops of the same score. Between-class distance is the mean distance between class centroids. Their ratio is how separable the classes are: high means tight, well-separated clusters.

Both sets have the same number of crops per class, so no part of this is a sample-size artefact.

Code 
# 2.1
def spread(F, y):
    within = []
    for c in range(7):
        A = F[y == c]
        d = np.linalg.norm(A[:, None] - A[None], axis=-1)
        within.append(d[np.triu_indices(len(A), 1)].mean())
    cents = np.stack([F[y == c].mean(0) for c in range(7)])
    bc = np.linalg.norm(cents[:, None] - cents[None], axis=-1)
    return np.array(within), bc[np.triu_indices(7, 1)].mean(), cents

4. The linear probes

A linear probe is logistic regression fitted on a fixed feature space. It cannot invent features, only reweight the ones it is handed, so its accuracy measures whether the class is already legible in that representation.

Four numbers, all with the same model class and the same features:

fitted on tested on what it tells you
real real (5-fold CV) how legible severity is for real crops
real generated do generated crops obey the real class structure
generated generated (5-fold CV) how legible severity is for generated crops
generated real does anything learned from generated crops transfer

Features are standardised inside the pipeline so the fit is not dominated by whichever activations happen to have the largest scale.

Code 
# 4.1
def probe():
    # No multi_class= argument: it was removed in recent scikit-learn, and multinomial
    # is the default for multiclass problems there anyway.
    return make_pipeline(StandardScaler(), LogisticRegression(max_iter=2000))


cv = StratifiedKFold(5, shuffle=True, random_state=42)
rr = cross_val_score(probe(), Fr, yr, cv=cv).mean()
gg = cross_val_score(probe(), Fg, yg, cv=cv).mean()
rg = probe().fit(Fr, yr).score(Fg, yg)
gr = probe().fit(Fg, yg).score(Fr, yr)

6. The same questions in a feature space fitted to nothing

Everything above lives in the feature space of a CNN trained on real crops, so generated images are being judged through a lens fitted to their competitor. That is a real objection and it cannot be answered from inside that space.

The Chapter 2 features answer it. They are twelve hand-crafted scalars – Otsu segmentation of the lesion, then means, spreads and pixel counts over the resulting regions (chapter2_features.py, ported from uv-agroinfiltration-dataset/analyses/10_segmentation_and_feature_extraction/). Nothing in them is fitted to anything. Identical arithmetic is applied to both sets, so if the conclusions survive here, the lens was not driving them.

6.1 Does the port work, and are the channels the right way round?

Two things have to be checked before any comparison is worth reading. The port must reproduce Chapter 2’s published numbers, and the channel order must be right – these crops are BGR (cv.imread), where the R original was RGB, so a wrong greenness would silently invert the lesion.

Chapter 2 reports two AUCs for separating score 0 from non-zero: 0.944 for greenness bimodality (sep) and 0.451, no better than chance, for segmented lesion area (frac_g_gt_r). Both must come back.

6.2 Diversity and separability, recomputed

The features are on wildly different scales (sep is a ratio in [0, 1], mean_green runs to 255), so distances need standardising first. The scaler is fitted on the real crops only and then applied to both, which is the exact analogue of using a real-trained CNN’s feature space – the real data defines the units, and generated crops are measured in them.

Code 
# 6.2
sc = StandardScaler().fit(Cr)
Zr, Zg = sc.transform(Cr), sc.transform(Cg)


def spread_and_sep(Z, y):
    cents = np.stack([Z[y == c].mean(0) for c in range(7)])
    within = np.mean([np.linalg.norm(Z[y == c] - cents[c], axis=1).mean() for c in range(7)])
    between = np.mean([np.linalg.norm(cents[a] - cents[b])
                       for a in range(7) for b in range(a + 1, 7)])
    return within, between, cents

7. Interpretation and Discussion

Two of the three hypotheses are dead, and the third is now supported by a much sharper piece of evidence than the one this analysis was designed around.

Hypothesis 1 (mode collapse) is wrong, in both feature spaces. Generated crops are 1.84x more spread out within a class than real ones in the CNN space and 1.42x in the Chapter 2 space, at every score without exception (per-class ratios 2.40 at score 0 down to 1.44 at score 6). Their classes are also less separable, not more: the between-over-within ratio is 0.70 against the real crops’ 1.40 in the CNN space, and 0.86 against 1.19 in the Chapter 2 space. Two spaces with nothing in common agree on the direction and roughly on the size. Mode collapse cannot be what produced 97%.

Hypothesis 2 (memorisation) is wrong too. Each generated crop’s nearest real crop of the same class sits at distance 8.42, against 4.49 for real-to-real nearest neighbours. Generated crops are nearly twice as far from real ones as real ones are from each other. This had to be checked separately because the Frechet distance cannot see it – a perfectly memorising generator scores better on that metric than two halves of the real data do.

Hypothesis 3 (a class-conditional shortcut) is what survives, and section 6 is why. The argument runs on one comparison:

real -> real generated -> generated
linear probe, CNN features 0.639 0.763
linear probe, Chapter 2 features 0.606 0.602
CNN trained from scratch 0.646 0.9986

For real crops all three rows agree at roughly 0.61-0.65. Twelve hand-crafted numbers, a linear read-out of a CNN’s penultimate layer, and 8,640 CNNs searched over a grid all land in the same place, which says the severity signal in real crops is essentially fully exposed and there is no hidden extra to find.

For generated crops the same three rows read 0.602, 0.763 and 0.9986. Roughly 40 points of accuracy are available to a classifier that can invent its own features and are absent from both fixed representations – including one with no learned component anywhere in it. The Chapter 2 row is the strong version of the claim, because “the lens was fitted to real crops” is not available as an objection to Otsu thresholding and arithmetic means.

That gap is the signature of a generator fingerprint. A conditional GAN’s discriminator only asks whether an image looks real for its label, so any consistent per-class marker satisfies the objective. A fresh classifier finds it immediately. Neither real crops nor any severity-related measurement carries it.

The generator did learn real severity cues, which section 6.3 shows directly and is the genuinely encouraging result. All twelve interpretable features still track severity in generated crops, and not one of them flips sign. The correlations weaken slightly and uniformly – lesion greenness from rho 0.83 to 0.72, within-lesion brightness spread from 0.79 to 0.63, greenness bimodality from 0.76 to 0.66 – which is a generator that renders the right cues slightly less crisply, not one that replaced them. Consistent with that, a probe fitted on generated crops scores 0.575 on real ones against 0.639 for a probe fitted on real crops (0.506 against 0.606 in the Chapter 2 space): 85-90% of real-data legibility survives the transfer (0.900 and 0.835 of the respective real-to-real figures).

So the generated crops are not junk. They carry real severity information and a shortcut that dominates whenever a classifier is free to use it. That distinction is what makes augmentation worth trying: mixing real and generated crops gives the classifier a reason not to take the shortcut, which training on generated data alone never did.

One concrete defect: the severity scale is displaced at the top end. Generated centroids for scores 0-3 and 6 sit nearest their own real counterparts, but score 4’s centroid is nearest real score 5, and score 5’s is nearest real score 6. The displacements (3.7 to 6.8) are comparable to the entire real within-class spread of 7.93. The generator systematically renders high-severity classes as more severe than the real scale does. If generated crops are used for augmentation, the top classes are the ones to watch.

What this means for the 512-config run. None of the metrics currently recorded would detect any of this. The Frechet distance is blind to memorisation, says nothing about within-class structure, and cannot distinguish a generator that encodes severity the way real crops do from one that invents a marker – so selecting on it selects for the wrong thing. The acceptance test for a useful generator is instead the transfer probe: fit a logistic regression on generated crops, score it on real ones, and require it to approach the real-to-real figure (0.639 in CNN features, 0.606 in Chapter 2 features). That is one cheap number per generator and it measures the thing that actually matters, which is whether the generated crops encode severity the way real crops do.

What is still open. The shortcut has been shown to exist and to be invisible to both feature spaces, but it has not been identified – nothing here says what the per-class marker physically is. The natural next step is adversarial: train a small classifier on generated crops, then attribute its predictions with the Grad-CAM and SHAP machinery already built in analyses/06_cnn_attention_vs_lesion. If the attribution lands away from the lesion, that localises the fingerprint and would make it fixable.
