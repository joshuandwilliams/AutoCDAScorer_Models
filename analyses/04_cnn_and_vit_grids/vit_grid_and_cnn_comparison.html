The Medoid ViT grid: what the 2,592 configs show, and how they compare to the CNNs

Date: 09/09/2026

GOHREP

Goal:

Analyse the completed Medoid-ViT grid search (2,592 configs, 5-fold CV) on the same footing as analyses/03 and analyses/04 did for the CNN grid, and then compare the two model classes. Four questions: (1) did the search actually complete and are the numbers trustworthy; (2) is the top of the ViT grid a rankable ordering or a noise plateau, as it was for the CNNs; (3) which hyperparameters move accuracy, and in particular did the axes added to this grid earn their cost; (4) how does the best ViT compare with the best CNN, and what can and cannot be concluded from that comparison.

Hypotheses:

  1. The ViT grid will show the same noise plateau as the CNN grid. analyses/03 found ~210 CNN configs statistically tied at the top and CV-to-test correlation collapsing from 0.89 to 0.04 within the top 100. Nothing about swapping the architecture should change the measurement noise, which is set by the size of the evaluation set.
  2. Learning rate will dominate, as it did for the CNNs (analyses/04: mean |SHAP| for learning rate was ~29x that of dropout).
  3. The two capacity axes this grid added — projection_dim 256 and mlp_ratio 4 — will not pay for themselves. They were added because a single pilot config with projection_dim 128 scored best, which is a sample of one.
  4. The best ViT and the best CNN will land within noise of each other, consistent with analyses/03’s conclusion that ~62-65% is a ceiling set by label noise rather than by architecture.

Rationale:

A grid search produces two things: a best model, and a dataset of 2,592 (hyperparameters → accuracy) observations. analyses/03 showed the first is largely noise, which makes the second the more valuable output. Treating the grid as data is also the only way to answer whether the grid was well designed — a question that matters here because this grid’s shape was chosen partly on the basis of one pilot run, and that reasoning deserves auditing against 2,592 results.

The CNN/ViT comparison is matched: models/03_Medoid_CNN_RandomSearch and models/04_Medoid_ViT_RandomSearch both ran the same 5-fold CV harness, with the same cv_seed, on the same medoid_64 dataset. Nothing differs but the architecture and its hyperparameter grid, so a difference here is attributable to the model class rather than to the crop.

Experimental plan:

  1. Validate: every grid index present exactly once, and a saved model reproducing its recorded test accuracy.
  2. Distributions, then the noise-floor treatment of analyses/03 applied to the ViT grid.
  3. A random-forest surrogate over the hyperparameters, as in analyses/04, plus explicit per-axis marginals with confidence intervals.
  4. A direct audit of the three grid-design decisions, and a costing of what a corrected grid would have been.
  5. CNN versus ViT, matched on the same dataset, splits and CV seed.

1.2 Load both grids, and check the ViT grid is complete

A self-scheduling grid can silently lose a config: JobCounter.claim() advances the shared counter before training, so a task killed mid-config leaves that index claimed and never trained, absent from the results with no error raised anywhere. That is exactly what the --max_configs clean-exit budget was added to prevent, so the first thing to check is whether it worked.

def load_grid(root):

3. Is the top of the ViT grid rankable, or a noise plateau?

analyses/03 established the method for the CNN grid. avg_vaf is the mean accuracy over 5 folds, and because each pooled image appears in validation exactly once, it is effectively one accuracy measured over all N = 2,289 train+val images. The standard error of such a proportion is sqrt(p(1-p)/N), and the standard error of the difference between two configs is sqrt(2) times that.

Code 
# 3.1
N_CV = 2289
N_TEST = 308

top = vit.sort_values("avg_vaf", ascending=False).reset_index(drop=True)
p_top = top.avg_vaf.iloc[0]
se_cv = np.sqrt(p_top * (1 - p_top) / N_CV)
se_diff = np.sqrt(2) * se_cv
se_test = np.sqrt(p_top * (1 - p_top) / N_TEST)
spread100 = top.avg_vaf.iloc[0] - top.avg_vaf.iloc[99]

print(f"best avg_vaf                       {p_top:.4f}")
print(f"SE of one config (N={N_CV})        {se_cv*100:.2f} pp")
print(f"SE of a difference                 {se_diff*100:.2f} pp")
print(f"top-100 spread                     {spread100*100:.2f} pp "
      f"= {spread100/se_diff:.2f} difference-SE")
print(f"SE on the test set (N={N_TEST})      {se_test*100:.2f} pp "
      f"(95% CI +/-{1.96*se_test*100:.1f} pp)")

# One-sided two-proportion z-test of every config against the best.
z = (p_top - vit.avg_vaf) / se_diff
for alpha, label in [(0.05, "5%"), (0.01, "1%")]:
    crit = normal_dist.ppf(1 - alpha)
    print(f"configs NOT significantly worse than the best at {label}: {(z < crit).sum()}")

This count is conservative: all configs share the same CV folds (cv_seed is fixed at 42 across every task), so their errors are positively correlated and the true difference-SE is smaller than the independent-proportions value used here. It also ignores training stochasticity. analyses/04 measured that separately on the CNN grid, where 960 triples of functionally identical configs gave a median within-triple SD of 1.00 pp — the same magnitude as the sampling SE above.

3.3 Extreme-value check

Over M noisy configs the largest observed value exceeds the true mean by roughly sigma * sqrt(2 ln M) through selection alone. If the winner’s margin is smaller than that, it is within what noise produces without any config being genuinely better.

Code

4.3 Per-axis marginals, with uncertainty

Gini importance says an axis matters but not which value to choose. The marginal mean of avg_vaf at each level, with a 95% CI on the mean, says that directly. The CI is what separates a real level difference from grid noise.

Code 
# 4.3
axes_to_plot = varying + ["reg"]
fig, axs = plt.subplots(3, 3, figsize=(12, 8))
for ax, col in zip(axs.ravel(), axes_to_plot):
    g = work.groupby(col, dropna=False)["avg_vaf"].agg(["mean", "std", "count"])
    ci = 1.96 * g["std"] / np.sqrt(g["count"])
    xs = np.arange(len(g))
    ax.errorbar(xs, g["mean"], yerr=ci, fmt="o-", color="#4C72B0", capsize=3)
    ax.set_xticks(xs)

5. Auditing the grid design

This grid was not the obvious one. Three decisions were made before it ran, and 2,592 results are now available to judge them. Two of the three were made on the evidence of a single pilot config, which analyses/03 is precisely the argument against.

Marginal means alone would be misleading here, because the levels are not balanced across the other axes in a way that guarantees comparability. Two views are reported: the marginal mean, and the share of the global top-100, which asks whether a level ever produces a competitive model.

Code 
# 5.1
def audit(col, note):
    g = work.groupby(col, dropna=False)["avg_vaf"].agg(["count", "mean", "max"])
    g["top100"] = top.head(100).assign(reg=top.head(100)["reg"].fillna("None")) \
                     .groupby(col, dropna=False).size().reindex(g.index).fillna(0).astype(int)
    g["top100_rate"] = (g.top100 / g["count"]).round(4)
    print(f"--- {col} --- {note}")
    print(g.round(4).to_string())
    print()

7. Interpretation and Discussion

  • The search is sound, and the clean-exit budget is what made it so. All 2,592 indices appear exactly once across 138 task-lifetimes. That is the outcome the --max_configs budget existed to guarantee: because claim() advances the shared counter before training, an OOM-killed task would have left its index claimed and never trained, missing from the results with nothing raised anywhere. The failure mode is silent, so a completeness assertion belongs in every analysis that reads a self-scheduled grid, not only this one.

  • The ViT plateau is if anything tighter than the CNN’s. The top-100 spans 1.31 pp against a difference-SE of 1.41 pp, so the entire top hundred fits inside 0.93 of one standard error — where analyses/03 found 1.64 for the CNN grid. 351 configs are not significantly worse than the winner at 5%, and that count is conservative for the same two reasons as before: shared CV folds correlate the errors, and training stochasticity is excluded. Changing the architecture did not change the measurement noise, because that is set by the 2,289 evaluation images, not by the model.

  • The winner’s curse reproduces exactly. The CV-best config ranks 138th of 2,592 on the held-out test set, and CV-to-test correlation falls from 0.928 across the whole grid to ~0.21 within the top 1,000 and 0.10 within the top 250. The winner’s margin over the top-500 mean is 1.88 pp against the 2.47 pp that selecting a maximum from 2,592 noisy draws produces on its own. The ranking carries real information across the full range and none of it survives into the plateau.

  • Learning rate is the whole story, and it acts as a switch rather than a dial. It takes 0.557 of the Gini importance, more than double projection_dim at 0.215. The mechanism is visible in the distribution: 307 configs (11.8%) sit at chance, and every one of them uses learning_rate 0.01. The grid is bimodal because one learning-rate level fails to train at all, so most of what the surrogate “explains” is the separation of dead configs from live ones, not fine discrimination among good ones.

  • Inside the plateau the surrogate has nothing left. OOB R² falls 0.963 → 0.279 (top-500) → −0.032 (top-250). A negative out-of-bag R² means the forest predicts worse than the pool mean, which is what zero remaining signal looks like. This is a sharper collapse than the CNN grid’s 0.933 → 0.337, and it closes the same loop analyses/04 drew: hyperparameters determine whether you reach the plateau, and nothing determines where on it you land.

  • Two of the three grid-design decisions did not pay for themselves, and both were made from a single pilot run. projection_dim was extended to 256 because one pilot config at 128 scored best. In the event 256 is the worst of the four levels (marginal mean 0.4693) and contributes 16 of the top 100 against 59 for projection_dim 32 — the optimum is at the small end, in the opposite direction to the extension. mlp_ratio 4 separates from 2 by 0.0040, well inside the 0.0100 single-config SE. Restricting to projection_dim <= 64 with mlp_ratio fixed at 2 would have been 648 configs and roughly 68 GPU-hours instead of 2,592 and 273, and would have found a best avg_vaf of 0.6431 against 0.6466 — a gap of 0.25 difference-SE, which is indistinguishable. 75% of the compute bought a quarter of one standard error. The general lesson is the one analyses/03 already established and this grid re-learned the expensive way: a single configuration is not evidence about an axis.

  • The regularisation axis was cheap and inert. L2 versus none differs by 0.0014 in marginal mean, and the two strengths by 0.0014. Both are an order of magnitude below the 1.00 pp noise floor. Splitting the grid into sub-grids so reg=None was not duplicated across strengths avoided 864 redundant configs, which was worth doing, but the axis itself answered nothing.

  • On matched data the two architectures are indistinguishable. Both grids ran the same harness and cv_seed on the same medoid_64 dataset, so this is a clean architecture comparison. Best avg_vaf is 0.6466 (ViT) against 0.6457 (CNN), a gap of 0.09 pp against a 1.41 pp difference-SE — 0.06 SE, which is as close to identical as the measurement can resolve. The best test accuracy reached by any config is 0.6818 in both grids. The CV-selected models differ by more (0.6429 against 0.6169), but that is 1 test-SE and is the winner’s-curse lottery described above rather than an architecture effect. The ViT reached this with 2,592 configs and 273 GPU-hours against the CNN’s 8,640 configs and 1,194 CPU-hours, so the architectures tie on accuracy while differing in search cost and hardware, which are not comparable in the same units.

  • Both model classes remain below human exact agreement and above it on near-miss. Against the 0.6892 exact and 0.9280 near-miss that analyses/02 measured for human raters on these same 308 CDAs, the best ViT reaches 0.6818 and 0.9903. The first of those is a maximum taken over 2,592 configs selected on the test set, so it is optimistically biased and should not be read as a headline; the CV-selected model scores 0.6429. The near-miss figure is the robust one, and it says the same thing as every earlier analysis: the coarse task is solved and the residual error is adjacent-score confusion, which is where the human raters disagree too.

  • What to do next. With the architecture question answered as a tie, the remaining headroom is not in the model. Since 351 ViT configs are statistically tied here, the useful object is the committee rather than the argmax: analyses/05 showed a 100-model CNN vote matched the best single model with none of the per-model lottery. Both grids now have a kept top-100 on the same splits, so the informative test is a mixed CNN+ViT committee, where the two classes may fail on different images even though they reach the same accuracy separately. Their agreement rate is the quantity to measure first, because a tie in accuracy with low agreement is exactly the situation in which ensembling pays.
